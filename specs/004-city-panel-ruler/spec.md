# Feature Specification: 城市面板与控制人导航

**Feature Branch**: `004-city-panel-ruler`  
**Created**: 2026-04-03  
**Status**: Draft  
**Input**: User description: "创建点击城市后，展示这个城市的城市面板。每个城市应该有一个控制人。可以点击控制人来跳转到人物详情。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看城市面板 (Priority: P1)

玩家点击地图上的城市后，系统展示该城市的专属面板，让玩家能够快速了解城市的基本信息和当前状态。

**Why this priority**: 城市面板是玩家与城市交互的核心入口，没有它玩家无法获取城市相关信息，直接影响基础游戏体验。

**Independent Test**: 可以通过在地图上点击任意城市来独立测试，验证城市面板是否正确显示该城市的对应信息。

**Acceptance Scenarios**:

1. **Given** 玩家处于游戏主界面且地图上存在城市, **When** 玩家点击一个城市, **Then** 系统展示该城市的城市面板
2. **Given** 城市面板已经打开, **When** 玩家点击另一个城市, **Then** 面板内容切换为新选中城市的信息
3. **Given** 城市面板已经打开, **When** 玩家执行关闭操作（如点击面板外区域或关闭按钮）, **Then** 城市面板关闭

---

### User Story 2 - 查看城市控制人 (Priority: P1)

每个城市的面板中必须显示该城市的控制人信息，让玩家明确知道当前是谁在统治这座城市。

**Why this priority**: 控制人是城市身份的重要组成部分，与游戏的政治、外交和角色扮演系统紧密关联，必须在城市面板中直观呈现。

**Independent Test**: 可以打开任意城市的面板来独立测试，验证面板中是否正确显示了该城市的控制人标识。

**Acceptance Scenarios**:

1. **Given** 玩家打开了一个有控制人的城市的面板, **When** 玩家查看面板内容, **Then** 面板中清晰显示该城市的控制人名称和/或头像
2. **Given** 玩家打开了一个城市的面板, **When** 该城市没有明确的控制人, **Then** 面板显示相应的无控制人状态（如"无主"或空状态）

---

### User Story 3 - 跳转到控制人详情 (Priority: P2)

玩家在城市面板中点击控制人后，系统应导航到该控制人的人物详情页面，让玩家能够深入了解该角色的背景、属性和状态。

**Why this priority**: 从城市面板到人物详情的导航是重要的信息流转路径，能够提升玩家探索角色关系网络的效率，但可以在城市面板基础功能完成后实现。

**Independent Test**: 可以在城市面板显示控制人的情况下点击控制人区域来独立测试，验证是否正确跳转到对应的人物详情页面。

**Acceptance Scenarios**:

1. **Given** 城市面板中显示了控制人, **When** 玩家点击控制人区域, **Then** 系统打开该控制人的人物详情页面
2. **Given** 城市面板中控制人区域可点击, **When** 玩家悬停在控制人区域上, **Then** 系统提供视觉反馈（如高亮、光标变化等）提示该区域可交互
3. **Given** 城市面板中显示"无主"状态, **When** 玩家尝试点击该区域, **Then** 系统不执行跳转操作

---

### Edge Cases

- 当玩家快速连续点击不同城市时，面板内容应始终与最后选中的城市保持一致，不出现信息错乱
- 当城市控制人在游戏过程中发生变更时，城市面板应在下次打开时反映最新的控制人信息
- 如果人物详情页面已经在打开状态，再次点击同一控制人时，应避免重复打开多个相同页面

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 玩家点击地图上的城市后，系统必须展示对应城市的城市面板
- **FR-002**: 城市面板必须显示该城市当前的控制人信息
- **FR-003**: 点击城市面板中的控制人区域后，系统必须导航到该控制人的人物详情页面
- **FR-004**: 当城市没有控制人时，城市面板必须显示无控制人的相应状态，且不可触发人物详情跳转
- **FR-005**: 城市面板关闭后再次打开时，必须显示该城市最新的信息（包括控制人）

### Quality Requirements *(与宪法 I. 代码质量 对齐)*

- **QR-001**: 代码必须遵循 P3C 规范，零 ERROR 级别警告
- **QR-002**: 公共 API 必须包含完整的 JavaDoc 注释
- **QR-003**: 方法长度不得超过 50 行，圈复杂度不得超过 10

### Testing Requirements *(与宪法 II. 测试标准 对齐)*

- **TR-001**: 单元测试覆盖率必须达到 80%（核心业务 ≥90%）
- **TR-002**: 所有测试必须可在 CI 环境中自动执行
- **TR-003**: 必须包含至少一个集成测试验证从点击城市到跳转人物详情的端到端流程

### User Experience Requirements *(与宪法 III. 用户体验一致性 对齐)*

- **UX-001**: 交互必须符合既有 UI 模式（左键选择、右键菜单等）
- **UX-002**: 用户操作必须在 100ms 内提供视觉/音频反馈
- **UX-003**: 错误信息必须用户友好，说明问题原因和解决方案
- **UX-004**: 所有用户可见文本必须支持本地化

### Performance Requirements *(与宪法 IV. 性能要求 对齐)*

- **PR-001**: 功能不得导致帧率低于 60 FPS（最低 30 FPS）
- **PR-002**: 内存占用增量必须明确预算，不得超出模块分配
- **PR-003**: 加载/保存操作不得超时（存档 ≤5 秒）

### Key Entities *(include if feature involves data)*

- **城市 (City)**: 游戏世界中的定居点，拥有名称、人口、地理位置等属性。每个城市关联一个控制人。
- **控制人 (Ruler/Controller)**: 统治或管理城市的角色，是人物实体的一种身份状态。控制人拥有独立的详情页面。
- **城市面板 (City Panel)**: 展示城市信息的 UI 组件，包含城市基本信息和控制人展示区域。
- **人物详情 (Character Details)**: 展示角色完整信息的页面或面板，可通过控制人入口导航进入。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家点击城市后，城市面板在 200ms 内完成展示
- **SC-002**: 城市面板中控制人信息的显示准确率达到 100%（与城市数据一致）
- **SC-003**: 90% 的测试用户能够在首次使用时成功通过点击控制人跳转到人物详情
- **SC-004**: 从点击城市到查看人物详情的完整操作流程可在 3 次点击内完成
